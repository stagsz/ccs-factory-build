# Factory backlog

`/factory next` takes the first unchecked item, creates a job and marks it `[~]` with the job id.
When the job ends, `board.mjs stage` closes the line: `[x]` merged, `[!]` failed.
Format: `- [ ] Short title :: optional longer request for the spec writer`

- [x] Decide merge failures by MERGE_HEAD, not git's message :: SKILL.md step 5 (`local` merge) tells a conflict from a refused merge by reading git's output. A merge a git hook rejects can fail after it started, leave MERGE_HEAD set, and then step 7's record commit would finish an untested merge. Change claude-setup/skills/factory/SKILL.md so that whenever `git merge` exits non-zero, the orchestrator runs `git rev-parse -q --verify MERGE_HEAD`: if it succeeds, run `git merge --abort` and park needs-human (conflict or rejected merge); if it fails, nothing started, so park needs-human as "merge refused". Never go on to tests or `merged` in either case. Also: the `--note` must carry only git's first `error:`/`CONFLICT` line with double quotes, `$` and backticks removed. Pin the new wording in tests/skill.test.mjs. Do not edit .claude/.
